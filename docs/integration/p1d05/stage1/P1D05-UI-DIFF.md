## 3. 逐项差异对照 / Differences

| 维度 | 原版 | 当前 | 差异性质 |
|---|---|---|---|
| 整体骨架 | 单页全宽，纵向单列 + 双列汇总 | 左栏编辑 + 右栏 A4 预览双栏 | **结构性差异** |
| 客户 / 订单信息 | **页面最底部** | **左栏最顶部** | 顺序颠倒（最显眼差异） |
| 报价计算参数 | 顶部独立参数条，5 项集中常驻 | 散在「高级/内部参数」，仅 fx / incoterm 上移 | 缺独立参数区 |
| 风险提示 | 独立 `warnbox` ⚠ 风险提示条 | 无（仅系统迁移提示） | 缺失 |
| 产品明细形态 | **卡片式**（A/B/C/D 区） | **表格行内编辑** | 交互形态不同 |
| 成本明细可见性 | **默认收起**（`_expanded`） | 常驻展开在每行 | 信息密度不同 |
| 汇总 / 折扣 / 运费 | 明细下方两列并列：汇总 + 其他、运费面板 | 三张独立卡片顺序排列 | 组织方式不同 |
| 内部核价区域 | 无独立面板，参数在顶部条 | 「高级 / 内部参数」常驻卡 | 当前更重 |
| 实时 A4 预览 | 无（走独立打印页） | 右栏常驻可编辑预览 | 当前增强能力 |
| 保存入口 | 防抖隐式保存，无按钮 | 显式「保存修改」 | 交互不同 |
| 五类单据转换 | 无（原版仅 Quotation/PI） | 复制 / 转换 QT→PI/SC/CI/PL | 当前增强能力 |
| 全局导航 | 顶部 6 项导航 | 左侧深色侧栏 11 项 | 外壳不同 |

**重要判断**：当前**字段基本齐全**（客户、产品、数量、单位、单价、成本、运费、定价参数、
成交价、条款、包装都有），问题主要是**区域顺序、卡片形态与信息密度**，不是缺字段。
因此改造应以「**重排 + 折叠**」为主，而不是新增输入项或新增面板 —— 符合任务书
「不增加不必要输入项，不让用户在多个复杂面板间来回切换」。

## 4. 字段与操作入口对应说明 / Field & action mapping

| 原版字段 / 入口 | 当前对应 | 位置变化建议 |
|---|---|---|
| 报价汇率 FX | `P1C.setPricingParam` / fx（已在订单信息卡） | 应回到顶部参数条，与其余 4 项并列 |
| 目标毛利率 / 销售费率 / 提成 / 亏损规则 | 「高级 / 内部参数」卡 | 上移到顶部参数条，常驻、修改即重算 |
| 产品搜索 + 手动新增临时产品 | 产品库卡片快速添加 / 行内手填 | 保留在产品明细区顶部 |
| 产品卡片 A 产品信息（缩略图/SKU/名称/规格/数量/单位） | 明细行内字段 | 保留全部字段，改为卡片呈现 |
| 产品卡片 B 内部成本 | 明细行内成本字段 | **默认收起**，点击展开 |
| 产品卡片 C 智能报价（建议单价 / 最终成交价） | 明细行内建议价 / 成交价 | 保留在卡片 C 区 |
| 整单汇总 / 其他（折扣、其他收费） | 「订单费用」+「核价汇总」 | 合并为明细下方左列汇总卡 |
| 运费面板（金额 / 已核实 / 单独收取 / 已计入产品成本） | 「运费明细（分组）」 | 合并为明细下方右列运费卡 |
| 订单信息：客户 Buyer 三态 | 关联客户下拉 + 客户卡/手填 | **移到底部**订单信息卡 |
| Incoterm / Named Place | 已在订单信息卡 | 保持（原版也在此卡） |
| Freight Markup / Valid Days / Payment Terms / Lead Time / Packaging | 订单信息卡 + 条款区 | 集中在底部订单信息卡 |
| ⚠ 风险提示 | 无 | 新增顶部提示条（只读展示，不新增输入项） |
| 确认报价 / 预览 / 归档 / 复制 | 导出 PDF / 打印 / 复制 / 转换 / 保存修改 | 操作条保留，不新增入口 |
| 250ms 防抖隐式保存 | 显式「保存修改」 | **建议保留显式保存**（数据安全性更强，且任务书要求保留编辑能力）；不强行改成隐式保存 |

## 5. 最小改造方向 / Minimal change direction (供确认，未实施)

1. **只重排、不重设计**：沿用现有 `Pages.quoteEdit` 的字段与全部 `oninput/onchange` 写入链
   （`Doc.termField` / `Doc.custField` / `P1C.set*` / `Doc.setField`），不改任何写入口、不新增字段。
   源码注释里已有这条「铁律」，改造应继续遵守。
2. 左栏顺序改为贴近原版：**① 顶部参数条（原 ⑥ 的定价参数上移）→ ② 风险提示条 →
   ③ 产品明细卡片（成本默认折叠）→ ④ 汇总/折扣 + 运费两列 → ⑤ 底部订单信息（客户）**。
3. 内部核算能力（费用分摊、国内/国际运费、核价汇总、成交价保护）**不删除**，统一收进
   「高级 / 内部核价」折叠区，避免多个复杂面板来回切换。
4. 右栏 A4 预览**建议保留**（属于编辑能力、且任务书要求保留），待用户确认。
5. 改动文件预计仅 `app/pages.js` + `app/app.css`；**不碰** `app/pricing.js`、`app/sheet-rc.js`、
   `app/model.js`、Schema V5、PDF 模板、产品库、客户库、历史单据。

## 6. 明确不做 / Out of scope

- 不重建项目、不引入新框架、不新增复杂模板系统。
- 不修改任何业务计算、定价公式、费用分摊逻辑、成交价保护。
- 不改动已验收的 RC 五类 PDF 整体版式（LOGO、分页、签名、汇总金额、条款区）。
- 不覆盖生产程序、不操作生产 userData、不迁移生产数据。
- 本阶段（调查）**未修改任何源码**；实施须等待用户对实物图来源与 §5 口径的确认。
