## 2. 三种"利润率"对照（V2 已按审核决定更正）

**定案：采用方案 A（润成现有算法）。**

### 2.0 target_margin 双模式定义（最后审核补充 §1：两模式定义不同，切换必须重算）

| | 含费模式（feeInPrice=1，新报价默认） | 不含费模式（feeInPrice=0，历史兼容） |
|---|---|---|
| 定义 | `target_margin = (1−fee)×markup/(1+markup)`——手续费已计入售价，该值即手续费后目标利润率 | `target_margin = markup/(1+markup)`——手续费不计入售价，该值**不含**手续费扣减 |
| 售价公式 | `suggested = cost_usd/(1−fee−target_margin)` = 成本×(1+markup)/(1−fee) | `suggested = cost_usd/(1−target_margin)` = 成本×(1+markup) |
| 40% 加成、3% 手续费 | target_margin=27.71%，售价=成本×1.4÷0.97 | target_margin=28.57%，售价=成本×1.4 |

**feeInPrice 语义（最后审核补充 §2 定案）**：
- `feeInPrice = 1`：含费模式（显式）。
- `feeInPrice = 0`：不含费模式（显式）。
- `feeInPrice = null`：**未知状态，不等于 1**。分历史来源处理：
  - **润成 V3 历史数据**：V3 源码缺省语义为含费（L155 `q.fee_in_price !== 0` 实证）——引擎按 V3 源码 1:1 保留此行为（K13 断言），仅适用于润成来源的数据；
  - **丝网盒子 v4 历史数据**：迁移时定价参数**保留 null，不自动判断报价模式**；用户主动重新定价时提示确认模式（引擎缺参告警 K16c 已具备；编辑器层 P1-C 在该告警存在时不得自动填价）；
  - **新建报价**：编辑器明确写入 feeInPrice=1（P1-C 落实）。
  - 引擎本身**不拥有** feeInPrice 的赋值权：它只按调用方传入的存储值计算并回显实际生效模式（totals.fee_in_price），"补默认值"属编辑器/迁移层职责。

基准公式（冻结，P1-A 按此实现）：

```
markup = 0.40（成本加成率，主要输入参数）
fee = 0.03（手续费，默认计入报价，feeInPrice=1）
target_margin = (1 − fee) × markup / (1 + markup)     ← 含费模式下的引擎 target_margin，非传统毛利率
suggested_price = cost_usd / (1 − fee − target_margin)
等价于：suggested_price = cost_usd × (1 + markup) / (1 − fee)

（不含费模式：target_margin = markup/(1+markup)，suggested_price = cost_usd/(1−target_margin) = 成本×(1+markup)）```

**基准算例（审核确认的正确数字，更正 V1 错误的 15.13 USD）：**

成本 100 CNY、fx=6.6、加成率 40%、手续费 3%：

| 量 | 数值 | 计算 |
|---|---|---|
| 建议售价（CNY） | **144.33** | 100 × 1.4 ÷ 0.97 = 144.3299 |
| **建议售价（USD）** | **21.868** | 144.3299 ÷ 6.6 = 21.868166… = **100×1.4÷0.97÷6.6**（测试内部保留足够精度，最终按报价币种精度舍入） |
| 手续费后目标利润率（=存储的 target_margin） | **27.71%** | 0.97×0.4/1.4 = 0.27714 |
| 传统毛利率（按实际售价 144.33 计） | **30.71%** | (144.33−100)/144.33 = 0.30713 |

引擎一致性验证：存储 27.71% 代入 `售价 = 成本USD/(1−0.03−0.27714)` = (100/6.6)/0.692857 = 21.868166 USD ✅。即"先按加成放大、再整体承担 3% 手续费"，与润成历史报价（249.18×1.4÷0.97÷6.6=54.49）完全一致。

**V1 错误更正记录（审计留痕）**：V1 表中"传统毛利率 28.57%"错在按未含手续费的 140 计算毛利，正确基准是实际售价 144.33 → 30.71%；V1"手续费后利润率 25.57%"同样错用 140 基数，正确为 27.71%；V1 一致性算例"15.13 USD"漏乘分母（100/6.6 只是成本折美元，未完成定价），正确为 21.868166 USD；V1 选项 B 算例"142.62"为错值（按 25.57% 直填的公式一致计算应为 140.00 CNY）。**本报告更正的只是 V1 报告文字中的算例数字，润成源码与 26 项测试预期值均无此错误、未做任何改动。**

**V1 曾列出的 A/B 口径分歧已由审核裁定，不再开放确认**：采用 A；界面同时显示成本加成率与手续费后目标利润率（27.71% 这类数值），不得把 target_margin 标记为传统毛利率；保留 fee_in_price=0 历史兼容计算能力，新报价默认 fee_in_price=1。

## 3. 老法（fee_in_price=0）口径说明

- 实际实现：`售价 = 成本USD / (1 − margin)`（fee 不进售价，从利润整单扣除，L358-360 有告警提示）
- ⚠️ 代码头注释写的是"老法售价=成本×(1+加成)÷汇率"——**注释与实现的公式形式不一致**（(1−margin) 分母形式 vs (1+markup) 乘法形式；仅当 margin=markup/(1+markup) 时等价）。测试 E1 证明实现取的是分母形式且 margin 语义为毛利率。迁移时以**实现为准**，注释差异已记录，不影响计算。

## 4. 成本确认语义差异（任务书 H 项 vs 现状）

任务书要求：null=未填写、0=明确确认为零、未确认不得作为正式成本依据。
润成现状：`cost_confirmed` 是独立布尔（1=已确认），成本四项数值 `||0` 缺省；**"确认"与"为零"是两个字段**，与任务书的"0=确认零"语义兼容但更细。
- 迁移映射建议：`cost_confirmed=1` → 已确认；`cost_confirmed=null/0` → 待确认（无论数值是否为 0）。
- 待确认时建议价显示为"参考值"不作为正式建议价——润成已有 ready 门（L437-444：blockers=0 且全部 cost_confirmed 才 ready），**满足任务书第 7 条"不允许未确认的成本自动生成正式建议价格"**，实现方式是整体 ready 门而非单价门，P1-C 编辑器上要把 ready 状态映射到建议价的呈现方式。
- 混合单位分摊（任务书 G 项）：润成按**数量**摊入，全单共用 totalQty；若明细行单位不同（如 set 与 m 混装），润成**当前不做单位一致性拦截**（只是总数平均）。**审核已定案（P1-A 落地）**：同单位按数量平均分摊；不同单位禁止自动按数量平均分摊；支持人工指定各行分摊金额，人工分摊总额必须严格等于原始费用；未完成分摊时显示"待分摊"，不生成正式含费用建议价；暂不做重量/体积加权。列入 P1-A 新增测试。

## 5. 价格保护机制现状（任务书 §6.4 六条）

- 引擎只产出 `suggested_price`；`used_price = final_price ?? suggested`（L257）
- final_price 一旦有值（用户手填），引擎建议价不参与 used_price（测试 I7 验证）
- "重新填入"在润成是编辑器按钮（用户主动），引擎层无自动覆盖
- **六条规则全部可满足，P1-C 按此实现即可**；第 5 条"重新计算只更新建议结果"对应引擎现状（每次 compute 全量重算，used_price 恒尊重手填值）

## 6. 个人提成（任务书 F 项）

润成现状：`order_commission = order_profit × commission_rate`（订单口径，L384），亏损单提成为 0（zero_on_loss，2026-11-04 管理层批准，L377）。不参与建议售价 ✅。默认 20% 需在丝网盒子设置页提供（settings 新增，非 doc 强制）。
